# Security Policy

Cockpit Kit is intended to be open source and operates on local, private knowledge repositories.

The `skill/scripts/serve.mjs` local server binds to loopback only by design and defaults to bearer-token cookie auth. Running it with `--no-auth` exposes the served tree to any local process or web page for as long as the server is running; only use `--no-auth` on a trusted machine.

The users and credentials store (`skill/lib/identity/store.mjs`, see `docs/identity-store.md`) must live outside the served root; the server refuses a path inside it, comparing real paths. The file is written atomically with mode `0600`, and loading refuses symlinks and group- or world-accessible files. Validation errors never include credential ids or public keys.

Passkey sign-in (`serve.mjs --passkeys`, see `docs/passkeys.md`) is opt-in and requires auth. Its settings come only from the command line: the relying-party id, the allowed origins, and the identity store path (an `identity_store` in `.cockpit/serve.toml` is refused, since anyone who can write the repo could point sign-in at their own store). The verifier accepts only `none` attestation and ES256 or RS256 keys, requires user verification, compares challenges and the rp id hash in constant time, and enforces single-use, two-minute challenges and the signature counter rule. Sign-in failures all return the same error, an unknown credential id is verified against a dummy key so that it costs the same as a bad signature, failed attempts are rate limited (per server, not per client), and the login page loads only same-origin assets under a strict Content-Security-Policy.

With `--passkeys`, the per-start server token authenticates nothing (no `?token=` URL, no `cockpit_serve` cookie). Instead the owner has a recovery token (see `docs/recovery.md`): 32 random bytes, stored only as a SHA-256 hash in `recovery.json` next to the identity store, printed once (only on an interactive first start or by `--rotate-token`, never to a non-terminal stdout, stderr, a response, or a file). It signs in only the owner, with a recovery session of at most 12 hours. Adding a passkey, creating an invite, and (later) changing delegations need a fresh passkey step-up (default 5 minutes) from every session, bound to that session, so neither a stolen recovery token nor a stolen session cookie alone can add a credential. Recovery-token attempts share a small rate limit (5 per minute) and are recorded in a bounded audit log of time, event, and result only, which drops failed attempts before anything else so a flood of them cannot push out a successful sign-in; a successful one is refused if it cannot be recorded. `--rotate-token` replaces the token and ends recovery sessions, which are also refused if they predate the current token. Keep the recovery token offline, like a password you hope never to use. A live session always wins over a token, so a member session cannot use the recovery token to register a passkey. When every passkey origin is https the session cookie is `__Host-cockpit_session`.

Members are added only through one-time invite links (see `docs/invites.md`), which only the owner can create from a live session with a fresh passkey step-up. An invite token is 32 random bytes; only its SHA-256 hash is stored, in `invites.json` next to the identity store with the same file safety. The token travels in the URL fragment, which browsers never send to the server or in a `Referer`; the invite page strips it from the address bar before making any request and sends it only in POST bodies, and the server never logs it. An invite is bound to the member it creates, single use (spent under a lock, so concurrent enrollments cannot both succeed), expires after 24 hours by default, and can be revoked; every invalid invite gets the same error. Treat an unused invite link like a password for a new member account until it is used or revoked.

Please report suspected security issues privately by opening a GitHub security advisory for this repository. If advisories are not available to you, open a minimal public issue that says you have a security report to share, without including exploit details or private data.

Do not include private Cockpit data, tokens, machine-specific paths, or other sensitive material in public reports.

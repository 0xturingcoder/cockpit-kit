# Security Policy

Cockpit Kit is intended to be open source and operates on local, private knowledge repositories.

The `skill/scripts/serve.mjs` local server binds to loopback only by design and defaults to bearer-token cookie auth. Running it with `--no-auth` exposes the served tree to any local process or web page for as long as the server is running; only use `--no-auth` on a trusted machine.

The users and credentials store (`skill/lib/identity/store.mjs`, see `docs/identity-store.md`) must live outside the served root; the server refuses a path inside it, comparing real paths. The file is written atomically with mode `0600`, and loading refuses symlinks and group- or world-accessible files. Validation errors never include credential ids or public keys.

Passkey sign-in (`serve.mjs --passkeys`, see `docs/passkeys.md`) is opt-in and requires auth. Its settings come only from the command line: the relying-party id, the allowed origins, and the identity store path (an `identity_store` in `.cockpit/serve.toml` is refused, since anyone who can write the repo could point sign-in at their own store). The verifier accepts only `none` attestation and ES256 or RS256 keys, requires user verification, compares challenges and the rp id hash in constant time, and enforces single-use, two-minute challenges and the signature counter rule. Only an operator with the server token can register a passkey. Sign-in failures all return the same error, an unknown credential id is verified against a dummy key so that it costs the same as a bad signature, failed attempts are rate limited (per server, not per client), and the login page loads only same-origin assets under a strict Content-Security-Policy. A passkey sign-in for the owner issues the existing server session cookie, so treat an owner passkey like the token.

Members are added only through one-time invite links (see `docs/invites.md`), which only the owner can create from a live passkey session. An invite token is 32 random bytes; only its SHA-256 hash is stored, in `invites.json` next to the identity store with the same file safety. The token travels in the URL fragment, which browsers never send to the server or in a `Referer`; the invite page strips it from the address bar before making any request and sends it only in POST bodies, and the server never logs it. An invite is bound to the member it creates, single use (spent under a lock, so concurrent enrollments cannot both succeed), expires after 24 hours by default, and can be revoked; every invalid invite gets the same error. Treat an unused invite link like a password for a new member account until it is used or revoked.

Please report suspected security issues privately by opening a GitHub security advisory for this repository. If advisories are not available to you, open a minimal public issue that says you have a security report to share, without including exploit details or private data.

Do not include private Cockpit data, tokens, machine-specific paths, or other sensitive material in public reports.
